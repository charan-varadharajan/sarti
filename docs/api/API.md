# API documentation

No endpoints exist in Stage 1.

Before the first endpoint is implemented, its documentation must state purpose
and owning module; authentication and authorization; request and response schema;
validation; status and stable error codes; idempotency; versioning; privacy and
security effects; and examples.

FastAPI-generated OpenAPI will be committed or generated in CI and validated
against implementation. Endpoint paths, payloads, and error formats remain open
until the first API design is reviewed.
